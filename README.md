# SISKU · черновой макет интернет-магазина

> **v0.19.0-draft · 09.10.2026.** Макет для оценки дизайна и функций владельцем
> магазина (волна v0.19.0 — «Сегменты клиентов»: «Статистика → Клиенты»
> вместо заглушки — новый / повторный / VIP / уснул, KPI (LTV, средний чек,
> доля выручки VIP), пороги в модалке, CSV сегмента, скрипт 30, check-repo
> v2.8; волна v0.18.0 — «Карточка клиента»: история заказов, варианты имён,
> история контактов, create_order v9). Название Sisku — временное заглушечное, будет заменено.
> Не является боевым сайтом: оплата и защита админки — следующих версий
> (см. SECURITY.md). Юридические страницы (политика ПДн, оферта) — черновые
> шаблоны с плейсхолдерами: privacy.html, offer.html, ссылки в подвале витрины.

Мультибрендовый бутик премиальной одежды и парфюмерии: витрина с каталогом,
корзиной и формой заказа + админ-панель (заказы, статистика, сборка, магазин,
управление, пользователи) с мок-авторизацией. Дизайн — «тихая роскошь»:
светлая тема Ivoire (основная) и тёмная Noir & Champagne, обе с переключателями,
контрасты WCAG 2.1 AA.

**Сайт-черновик:** https://paprekolyx.github.io/Sisku/

## Как править

- **Тексты сайта** — админка: «Управление → Сайт» (или Table Editor → `site_content`);
  витрина подхватывает после Ctrl + F5 без публикации кода.
- **Товары** — админка: «Магазин → Товары» (карточка или CSV); категории и бренды —
  соседние подвкладки.
- **Промокоды** — админка: «Управление → Промокоды»; их статистика —
  «Статистика → Акции».
- **Причины возврата** — админка: «Управление → Справочники» (внизу страницы);
  форма витрины берёт только активные причины; заявки — «Заказы → Возвраты»,
  статистика — «Статистика → Возвраты».
- **Клиенты** — админка: «Пользователи → Клиенты»: база пополняется сама
  из заказов; карточка клиента правит ФИО, контакты и комментарий.
- **Ключи базы** — только `assets/js/config.js`; там же константа версии.
- После публикации — обновить сайт с **Ctrl + F5**.

## Из учебного проекта сохранены сильные решения

- Заказ создаётся только серверной функцией `create_order()`: цены и остатки
  из базы, подмена суммы из браузера невозможна; одна транзакция; снапшоты
  цены, названия и варианта в позициях; анти-спам 3 заказа / 10 минут; honeypot.
- Статусная модель Jira-workflow (`status_transitions`) + журнал истории;
  смена статуса только через `admin_set_status()` с проверкой переходов.
- **Оплата — признак `is_paid` + дата, а не статус** (статус «Оплачен» удалён
  из модели в v0.2.0); с v0.15.0 признак можно менять и у отменённых заказов —
  деньги могли поступить или быть возвращены, событие пишется в историю.
- Промокоды проверяются сервером (`check_promo`), скидка пересчитывается
  в `create_order()` — публичного чтения кодов нет.
- Тексты в `site_content` правятся без кода; корзина в localStorage; скелетоны;
  экранирование вывода; блокировка повторной отправки форм.
- Маскирование контактов в админке + раскрытие кнопкой; CSV с BOM и `;`.
- Идемпотентные нумерованные SQL-скрипты; версия на всех страницах.

## Осознанные упрощения черновика

- Мок-авторизация: пароль 123456 живёт на странице входа и в JS, не в базе;
  нет ролевых ограничений страниц, сессий, 2FA, аудита (см. SECURITY.md).
- Запись каталога и справочников открыта анонимно (draft-политики 11–12) —
  для демонстрации CRUD без серверного API.
- Политика ПДн и публичная оферта — черновые шаблоны первой версии
  (privacy.html, offer.html) с плейсхолдерами [указать: …] и плашкой о черновом
  статусе; чекбокс согласия в форме заказа — с v0.15.0 (макет: блокирует
  отправку без отметки), запись факта согласия в БД и финальные юридические
  формулировки — в боевой версии после заполнения реквизитов и проверки юристом.
- Фото товаров — сгенерированные заглушки (с v0.17.0 — WebP 1200px, было
  JPEG 2048px); черновик фото хранит dataURL-ом в записи товара, боевой
  вариант — WebP-пайплайн загрузки в российском хранилище (M5).
- Предпросмотр карточки товара в админке — iframe с `sandbox` и статическими
  токенами брендбука (v0.17.0, находка A1 внешнего ревью): скрипты внутри
  предпросмотра не исполняются, значения токенов валидируются (hex/число).
- Возвраты (v0.16.0) — черновой контур: фото заявок — заглушка до файлового
  хранилища (M5); реализован только возврат, без обмена (решение — за
  аналитиком); юридические формулировки нейтральные до юрблока M4; карантин —
  счётчик `quarantine_qty` (складские движения с журналом — fp №3b, v0.28.0).
- База Supabase вне России: **только тестовые данные**, реальные ПДн не вводим.
