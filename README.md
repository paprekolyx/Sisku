# SISKU · черновой макет интернет-магазина

> **v0.2.0-draft · 20.09.2026.** Макет для оценки дизайна и функций владельцем
> магазина. Название Sisku — временное заглушечное, будет заменено.
> Не является боевым сайтом: юридические страницы, оплата и защита админки —
> следующих версий (см. SECURITY.md).

Мультибрендовый бутик премиальной одежды и парфюмерии: витрина с каталогом,
корзиной и формой заказа + админ-панель (заказы и статистика) без пароля,
доступ по ссылке. Дизайн — «тихая роскошь»: светлая тема Ivoire (основная)
и тёмная Noir & Champagne, обе с переключателями, контрасты WCAG 2.1 AA.

**Сайт-черновик:** https://paprekolyx.github.io/Sisku/
**Админ-панель:** `…/admin.html`

## Страницы

| Страница | Состав |
|---|---|
| `index.html` | о магазине, товары (фильтры: категория/бренд/наличие/сортировка, карточка товара с вариантами, корзина с «Очистить», форма заказа), условия заказа, контакты (+ ссылка на репозиторий), подвал с брендбуком |
| `admin.html` | заказы: список с фильтрами и поиском, карточка заказа со сменой статусов по модели переходов и признаком оплаты, маскирование контактов, выгрузка CSV; статистика: KPI, заявки по дням, воронка статусов с метриками времени, топ товаров, доставка/оплата (диаграммы или таблицы) |

Модальное окно **брендбука** — из подвала витрины: палитры обеих тем с hex
и контрастами, типографический масштаб, правила графики и фото.

## Стек

| Слой | Технология |
|---|---|
| Вёрстка | HTML5, CSS3 (дизайн-токены на CSS-переменных), vanilla JS без сборки |
| Шрифты | Prata + Manrope, локально (woff2, кириллица), без CDN |

| Хостинг | GitHub Pages (Deploy from a branch) |

## Инструкции

- **`docs/setup-repo-pages.md`** — репозиторий, загрузка файлов, включение Pages.
- **`docs/setup-supabase.md`** — вторая база в том же аккаунте Supabase,
  скрипты 01–04, импорт CSV (или скрипт 05 вместо CSV), куда вставить ключи.
- Скрипт **05** — запасной посев каталога без CSV; **06** — миграция живой базы
  к v0.2.0 (статус «Оплачен» убран из модели, Telegram вместо WhatsApp).

## Как править

- **Тексты сайта** — Supabase → Table Editor → `site_content` (ключи с подсказками).
- **Товары** — CSV в `data/` (импорт: brands → categories → products → variants)
  или скрипт `05_seed_catalog.sql`; что-то одно, не оба.
- **Ключи базы** — только `assets/js/config.js`; там же константа версии.
- После публикации — обновить сайт с **Ctrl + F5**.

## Из учебного проекта сохранены сильные решения

- Заказ создаётся только серверной функцией `create_order()`: цены и остатки
  из базы, подмена суммы из браузера невозможна; одна транзакция; снапшоты
  цены, названия и варианта в позициях; анти-спам 3 заказа / 10 минут; honeypot.
- Статусная модель Jira-workflow (`status_transitions`) + журнал истории;
  смена статуса только через `admin_set_status()` с проверкой переходов.
- **Оплата — признак `is_paid` + дата, а не статус** (в v0.2.0 статус «Оплачен»
  удалён из модели вовсе: миграция 06).
- Тексты в `site_content` правятся без кода; корзина в localStorage; скелетоны;
  экранирование вывода; блокировка повторной отправки формы.
- Маскирование контактов в админке + раскрытие кнопкой; CSV с BOM и `;`.
- Идемпотентные нумерованные SQL-скрипты; версия на всех страницах.

## Осознанные упрощения черновика

- Админ-панель без пароля (доступ по ссылке): нет пользователей, ролей, сессий,
  журналов; заказы читаются анонимно (политики `draft_anon_*`). Подробности
  и границы — в `SECURITY.md`.
- Нет политики ПДн, оферты, отзывов, промокодов, галерей, уведомлений владельцу.
- Фото товаров — сгенерированные заглушки; реальные фото даст контент-пакет.
- База Supabase вне России: **только тестовые данные**, реальные ПДн не вводим.

## Контакты

Черновые значения на сайте (телефон, e-mail, Telegram) — заглушки в `site_content`.
Вопросы по макету — владельцу проекта и аналитику; боевые контакты появятся
в контент-пакете волны 0.
