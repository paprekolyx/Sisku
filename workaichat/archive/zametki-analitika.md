## 1. Как я тестирую каждую волну (методика приёмки)

Сложился постоянный ритуал, отступления от него потом всплывают багами:

1. `python3 tests/check-repo.py` — выход 0 (целостность: файлы, ссылки, id,
   CSV, версии в шапках, SQL-регламент, баланс тегов).
2. `node --check` по всем JS-модулям (сейчас 19).
3. SQL-изменения — прогон на **живом PostgreSQL 15** дважды подряд
   (идемпотентность) + сверка самопроверки скрипта с ожидаемыми значениями
   до символа. С v0.14.0 добавила конкурентные сценарии двумя сессиями
   (двойная отмена, параллельные заказы одного клиента, лимит промокода).
4. Ручной чек-лист из `docs/update/update-v0XX.md` — каждый пункт глазами
   (путь — по структуре docs/ от 04.10.2026).
5. После публикации: синхронность сайта и репозитория (SITE_VERSION, ключи),
   Ctrl+F5.
6. Резервные каналы: зеркало `sisku-pages/` и архив `sisku-draft.zip`
   (GitHub из РФ нестабилен — показ владельцу не должен от этого зависеть).

**Уроки, вшитые в методику:**
- «Синтаксис ≠ структура»: `node --check` не ловит код, вклеенный внутрь
  чужого колбэка (F10) → в чек-листах пункт «проверить фичу СРАЗУ после
  открытия страницы, до срабатывания соседних действий».
- Самопроверки скриптов обязаны совпадать с фактом (F19: в комментарии «9»,
  фактически 8 политик).
- Гонки проверяются только двумя сессиями — одной они не воспроизводятся.
- PGlite в песочнице не жил (OOM) → нативный PostgreSQL 15, harness
  `pgtest/v4.sh`.

### v0.1.0-draft — старт

- **Задание (дословно, пост 1 — изучение и план, пост 2 — черновик):**
  > «Я хочу вместе с тобой создать еще один проект, уже для реальной торговли
  > моего парня. Что нельзя брать из учебного проекта: бд supabase - ищем
  > только российские решения (так как персональные данные для заказа можно
  > хранить только на российских серверах), брендбук, описания мастерской
  > (у него совсем другой бизнес), страница со статьей про кастомный заказ.»

  (пост 1);
  > «Окей, это хорошие планы. Давай в качестве черновика сделаем на github
  > (как учебный проект), просто чтобы посмотреть на дизайн, спросить мнение.»
  > «Важно - админ-панель без пароля, соответственно, в бд не надо ничего
  > делать для ролей, логов и паролей, просто доступ по ссылке.» «Все
  > юридические описания бизнеса, чеки и честный знак убираем для чернового
  > макета сайта. Название сейчас везде пишешь Sisku, потом будет заменено.
  > Будет много брендов.» (пост 2)
- **Сделано:** витрина (каталог, фильтры, карточка, корзина), заказ только
  через серверную `create_order()` (цены и остатки из базы — подмена суммы из

  (пост 5), «Посев csv вариантов товаров не синхронизирован с новой версией

  (явные id 1–8), плюс запасной посев скриптом 05 без CSV (грабля №5).

   ЗАМОРОЖЕНЫ (05.10.2026) — из дисциплины волны исключены** до отдельного

   волне, а только после отправки новой порции записок аналитика на вики
