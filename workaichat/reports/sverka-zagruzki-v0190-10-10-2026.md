### Находка 3 (🟡, систематическая). Ведущая строка CRLF — снова на всех 17 HTML + admin.css

Все 17 `*.html` и `assets/css/admin.css` на GitHub имеют **ровно одну
ведущую строку CRLF** (2 байта) перед первым значимым символом; содержимое
после неё байт-в-байт идентично рабочей копии (diff admin.html/admin.css —
единственная строка `1d0 < \r`). MD/JS/SQL-файлы пакета — чистые (без
ведущих строк). Вывод: артефакт затрагивает файлы конкретной загрузки
(вероятно, пакет HTML/CSS через «Upload files») — **грабля №17в
подтверждена в третий раз**: каждая такая загрузка добавляет +1 строку
(прежние 3–5 строк к v0.17.1 — результат нескольких перезагрузок одних и тех
же файлов). Рендеринг не затронут (doctype в первых байтах после одной
пустой строки — стандартный режим сохраняется); check-repo не проверяет
ведущие байты (кандидат в v2.9 — решение аналитика, черновик v0200 Д15 не
включает; можно добавить проверку «первые байты HTML = <!DOCTYPE» —
предложение разработчика). **Действие:** при следующей загрузке HTML —
очистка рабочей копией не поможет (загрузка снова добавит строку); вариант —
accept as documented artifact (рабочая копия остаётся эталоном) либо смена
способа загрузки HTML (git push / API — вне Web UI).
