Объясни, почему именно такие решения и языки программирования? Почему PHP, а не C\#?

### 11 ты

Отличный вопрос — он ровно про то, как принимаются инженерные решения. Короткий ответ: \*\*язык в этом проекте — не предпочтение, а следствие четырёх ограничений.\*\* Меняем ограничения — меняется и язык; ниже покажу, при каких условиях ответом станет C\#.  
\#\# Цепочка решений  
1\. \*\*Закон:\*\* ПДн покупателей — только на серверах в РФ (152-ФЗ) → Supabase и зарубежные облака вне игры для боевой версии.  
2\. \*\*Экономика:\*\* магазин стартует с нулевого/около нулевого бюджета и непредсказуемым трафиком → на старте нужен бесплатный или околонулевой тариф, а не VPS с платой с первого дня.  
3\. \*\*Эксплуатация:\*\* команду составляют системный аналитик и владелец без DevOps-навыков → не должно быть серверов, которые кто-то должен администрировать (обновления ОС, демоны, продление SSL, бэкапы руками).  
4\. \*\*Фронтенд:\*\* статический HTML без сборки (твоё исходное требование) → бэкенду остаётся роль «тонкого API на 14 эндпоинтов». Ему не нужны ни высокая производительность, ни сложные рантаймы.  
Из 1+2+3 следует хостинг: \*\*российский шеринг-хостинг с бесплатным тарифом (Beget)\*\*. А уже из хостинга следует язык: на таких тарифах из коробки, first-class, живёт \*\*PHP \+ MySQL\*\*. То есть PHP выбран не «вместо C\#», а потому что он — родной рантайм единственной площадки, удовлетворяющей закону, бюджету и отсутствию DevOps.

\#\# Почему PHP здесь выигрывает по совокупности  
\- \*\*Ноль инфраструктуры:\*\* PHP на шеринге не требует процесса, порта, демона и деплой-пайплайна — файл положен по FTP, он работает. SSL, бэкапы, обновления рантайма — забота хостера. Для C\# нужен кто-то, кто держит Kestrel за reverse-proxy на VPS и следит за ним ночью.  
\- \*\*Всё нужное встроено:\*\* сессии с HttpOnly/SameSite-cookie, PDO с подготовленными выражениями, transaction-API, mail — ровно тот набор, который нужен нашей модели авторизации и заказов, без внешних фреймворков.  
\- \*\*Рынок поддержки в РФ:\*\* PHP — самый массовый язык русскоязычного фриланса и студий. Если через год вам понадобится живой подрядчик дёшево и быстро, найти PHP-разработчика для маленького магазина на порядок проще, чем .NET-разработчика.  
\- \*\*Соответствие нагрузке:\*\* 10–50 заказов в день, витрина на несколько сотен товаров. Модель «один запрос — один процесс» для этого идеальна; асинхронность и сильные стороны сложных рантаймов просто негде применить.  
\- \*\*Преемственность:\*\* учебный проект и черновик уже зафиксировали философию «статика \+ тонкий серверный слой без Node/Docker» — PHP её продолжает, а не ломает.  
\#\# Почему не C\# (честно, по пунктам)  
ASP.NET Core — превосходная платформа: строгая типизация, производительность, инструментация. Но каждый её плюс требует среды, которой у нас нет:  
| Аргумент | Последствие для нашего проекта |  
|---|---|  
| .NET-рантайм нужен где\-то жить | Российский шеринг-хостинг .NET не даёт (Linux-шеринг \= PHP-центричный, Windows-шеринг — вымирающий и дорогой). Значит, платный VPS с первого дня |  
| VPS \= администрирование | Обновления, systemd-юнит, nginx, сертификаты, бэкапы, мониторинг — это DevOps-работа, которой в команде нет; её придётся покупать |  
| Деплой | \`dotnet publish\` \+ артефакты \+ пайплайн против «закинул файл по FTP». Для владельца, который правит сайт через веб\-интерфейс, второй путь радикально проще |  
| Масштаб преимуществ | Типизация и DDD окупаются на сложных доменах и больших командах; у нас домен — каталог, корзина, статусы, и он уже целиком выражен и проверен в черновике |  
| Стоимость владения | Лицензии/Windows-хостинг или VPS \+ час специалиста дороже всей остальной статьи расходов магазина на старте |  
\*\*Когда C\# был бы правильным ответом:\*\* у владельца уже есть .NET-команда или инфраструктура (например, интеграции с 1С/ERP/WMS на C\#), ожидается высокая нагрузка или сложный домен, есть бюджет на VPS и администрирование. В этом сценарии наш план не выбрасывается: контракт API зафиксирован язык-независимо (ADR-дисциплина из отчёта), поэтому бэкенд переписывается на ASP.NET Core \+ PostgreSQL, а фронтенд, дизайн и админка не меняются вообще. Именно для этого контракт эндпоинтов писался первым, до выбора реализации.  
\#\# Почему не другие кандидаты  
| Кандидат | Вердикт | Причина |  
|---|---|---|  
| Node.js/TS | Вариант B, не основной | На российском шеринге Node — гость второго сорта; зато он родной для Yandex Functions — поэтому вариант B (API Gateway \+ Functions \+ YDB) и держим как путь масштабирования |  
| Python | Возможно, но хуже | На Beget free Python есть лишь как CGI: медленно и неуклюже для сессий/REST; Flask/Django по-настоящему хотят VPS — возвращаемся к проблеме администрирования |  
| PostgreSQL вместо MySQL | Отложено, не отменено | PG объективно богаче (RLS, jsonb, plpgsql — на нём и жил черновик в Supabase), но на шеринге РФ дают MySQL; вся серверная логика всё равно переезжает в слой сервисов, где разница диалектов нивелируется. На VPS/Yandex вернём PG |  
| Готовая CMS (Bitrix, Woo) | Отклонено осознанно | Быстрый старт, но: платные лицензии/плагины, чужая supply-chain безопасности (патч-беговая дорожка), и главное — дизайн пришлось бы подгонять под тему, а у нас уже готовая и принятая владельцем айдентика |  
| Оставить Supabase | Невозможно | Закон, см. ограничение №1 |  
\#\# Страховка от «а вдруг решения изменятся»  
Весь план построен так, чтобы смена любого решения стоила дёшево: контракт API заморожен до реализации (меняем только папку \`api/\`), схема описана миграциями (переносится между СУБД), дизайн живёт в токенах (меняется без переписывания страниц), черновик и боевой проект разведены по репозиториям. Поэтому «PHP vs C\#» здесь — не религия, а строка в ADR-001 с перечисленными альтернативами и ценой выхода из решения. Если вводные поменяются (своя .NET-команда, рост нагрузки, инвестор с требованиями к стеку) — пишется ADR-001-rev2 и бэкенд меняется без трогания витрины.  
Если коротко одной фразой: \*\*C\# — правильный язык для сервера, которого у нас нет; PHP — правильный язык для сервера, который у нас будет бесплатно, в России и без администратора.\*\*
