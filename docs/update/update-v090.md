# Инструкция по обновлению черновика до v0.9.0-draft

**Куда смотреть:** этот файл — порядок применения обновления v0.8.0 → v0.9.0.
Формат: файлы сгруппированы по папкам источника, новый файл или обновляемый — не важно.

---

## 1. Файлы для загрузки (по папкам, откуда брать)

- **Корень репозитория:** `admin.html`, `assembly.html`, `shop.html`, `products.html`, `users.html`, `login.html`, `categories.html`, `brands.html`, `manage.html`, `sitecontent.html`, `sitemap.html`, `README.md`, `SECURITY.md`, `LICENSE.md`
- **assets/js/:** `admintheme.js`, `shop.js`, `categories.js`, `brands.js`, `manage.js`, `sitecontent.js`
- **assets/css/:** `admin.css`
- **supabase/:** `12_manage_policies.sql`
- **docs/:** `update-v090.md`
- **tests/:** `check-repo.py`

## 2. Версия

В `assets/js/config.js` поменять только строку
`const SITE_VERSION = '0.8.0-draft';` → `'0.9.0-draft';`. Ключи базы не трогать.

## 3. База, публикация и проверка

1. Supabase → SQL Editor → выполнить **`supabase/12_manage_policies.sql`**
   (самопроверка вернёт `write_policies = 9`).
2. Push в `main` → Pages за 1–2 минуты → **Ctrl + F5** на витрине и в админке.
3. Чек-лист:
   - верхние вкладки админки: **Заказы · Статистика · Магазин · Управление · Пользователи** (отдельной вкладки «Сборка» больше нет);
   - «Заказы»: подвкладки «Список заказов» и «Сборка» (обе кликабельны, активная подсвечена);
   - «Магазин»: подвкладки «Промокоды», «Категории», «Бренды», «Товары» — категории теперь отдельная страница;
   - «Бренды»: создание, правка кликом по названию, активация, удаление (бренд с товарами база не отдаст);
   - «Управление → Оплата и доставка»: таблицы способов с ценами/вилкой/активностью, создание и правка, тумблер «активен»;
   - «Управление → Сайт»: таблица site_content, поиск, правка значения кликом; баннер сверху объясняет, что сайт обновится после Ctrl+F5 без публикации кода;
   - «Управление → Карта сайта»: схема со всеми переходами, ссылки кликабельны;
   - **тема не «моргает»:** переключите светлую, обновите любую страницу админки — она сразу отрисуется светлой (раньше первая отрисовка была тёмной, потом скрипт переключал тему);
   - версия v0.9.0-draft видна на всех страницах, включая страницу входа;
   - скорость: админка заказов и статистика по-прежнему грузятся одним запросом (`rpc/draft_admin_bundle` в Network), «Сборка» — одним (`draft_assembly_bundle`); новые страницы делают по 1–2 лёгких запроса.

## 4. Финальная проверка

Локально перед коммитом: `python3 tests/check-repo.py` (выход 0 = зелёный).
Актуальный архив: `sisku-draft.zip`.

## Приложение: почему «моргала» тема

Цветовые токены выбираются атрибутом `data-theme` на `<html>`. Раньше атрибут
ставил `admintheme.js` на событии DOMContentLoaded — то есть **после** первой
отрисовки страницы: браузер успевал нарисовать дежурную тёмную тему из разметки,
затем скрипт читал localStorage и переключал на сохранённую светлую → видимое
моргание (FOUC). Теперь на всех страницах админки в `<head>` стоит инлайн-скрипт,
который ставит сохранённую тему **до** отрисовки первого кадра (тот же приём,
что и на витрине с `sisku_theme`), а `admintheme.js` только привязывает кнопку
переключения. Графики Chart.js читают палитру из атрибута при рендере,
поэтому перерисовка при переключении темы сохранена.

## Откат

Revert коммита; политики скрипта 12 снимаются `drop policy draft_anon_* …`
(чтение витрины не затрагивалось).
