# Инструкция по обновлению черновика до v0.13.0-draft

**Куда смотреть:** этот файл — порядок применения обновления v0.12.0 → v0.13.0.
Формат: файлы сгруппированы по папкам источника, новый файл или обновляемый — не важно.

---

## 1. Файлы для загрузки (по папкам, откуда брать)

- **Корень репозитория:** `index.html`, `login.html`, `privacy.html`, `offer.html`, `admin.html`, `assembly.html`, `shop.html`, `categories.html`, `brands.html`, `products.html`, `looks.html`, `manage.html`, `sitecontent.html`, `sitemap.html`, `brandbook.html`, `users.html`, `clients.html`, `README.md`, `SECURITY.md`, `LICENSE.md`
- **assets/js/:** `config.js` (только строка версии — см. п. 2), `admin.js`, `clients.js`, `brandvars.js`, `brandbook.js`, `site.js`, `admintheme.js`
- **assets/css/:** `admin.css`
- **supabase/:** `15_clients_and_promo_stats.sql`, `README.md`
- **docs/:** `update-v0130.md`, `tehpasport.md`, `feature-proposals.md`
- **tests/:** `check-repo.py`

Что в волне:

1. **Статистика → подвкладки** «Заказы / Акции / Администраторы / Клиенты»
   (admin.html + admin.js). Прежняя статистика целиком переехала на подвкладку
   «Заказы» без изменений. «Акции» — статистика промокодов по всем правилам
   заказов-статистики: период («Всё время» по умолчанию), KPI, график
   использования по дням, разрез по кодам с переключателем «Диаграмма /
   Таблица», блок «С кодом и без кода», своя выгрузка CSV. «Администраторы» и
   «Клиенты» — заглушки с планом функционала (feature-proposals, пункты 10 и 7
   + новые идеи: активность и скорость админов, лучшие сотрудники, журнал
   изменений каталога/промокодов/сайта; повторные продажи, VIP, «уснувшие»).
2. **«Промокоды» перенесены из «Магазина» в «Управление»** — подвкладки на всех
   страницах группы, активный таб топбара у shop.html, вкладка «Магазин» теперь
   ведёт на categories.html, карта сайта обновлена (заодно добавлены недостающие
   узлы «Комплекты» и «Брендбук»).
3. **Брендбук применяется к админ-панели** (раньше — только витрина):
   brandvars.js кэширует токены в localStorage и подключён в `<head>` всех
   страниц — палитра брендбука встаёт до отрисовки и в админке, и на витрине,
   и на юридических страницах; при переключении темы токены перечитываются
   (admintheme.js, site.js); сохранение цветов в брендбуке сразу обновляет кэш;
   производный токен `--accent-soft` пересчитывается из акцента (color-mix).
4. **Реальная клиентская база** (вместо мока v0.11.0): таблица `clients` +
   `orders.client_id` (скрипт 15). Один клиент = один телефон/e-mail
   (дедупликация по нормализованным ключам: 8→7, нижний регистр). Существующие
   заказы мигрированы: клиенты выделены из заказов и связаны. Новые заказы
   связывает клиента автоматически `create_order()` v5. Страница
   «Пользователи → Клиенты»: реальные данные одним RPC `draft_clients_bundle()`,
   поиск, сортировка кликом по заголовкам, пагинация по 30, маска + «глазик»,
   карточка клиента с агрегатами (заказы, суммы, даты) и сохранением правок
   в базу, выгрузка CSV. **Архитектура: две таблицы, а не три** — связь
   «один клиент → много заказов» (1:N) закрывается внешним ключом
   `orders.client_id`; промежуточная таблица нужна только для связей
   «многие ко многим» и здесь была бы лишней сущностью без смысла.
   Дополнительно: в заказах появились фактические суммы скидок
   `promo_discount` / `look_discount` (раньше хранился только итог — для
   статистики акций нужны отдельные числа; старые заказы пересчитаны из
   снапшотов позиций).

## 2. Версия

В `assets/js/config.js` поменять только строку
`const SITE_VERSION = '0.12.0-draft';` → `'0.13.0-draft';`. Ключи базы не трогать.

## 3. База, публикация и проверка

1. Supabase → SQL Editor → **проект sisku-draft** (в префлайте скрипт это
   проверяет) → выполнить **`supabase/15_clients_and_promo_stats.sql`**:
   таблица `clients` + политики, колонки `orders.client_id`,
   `orders.promo_discount`, `orders.look_discount`, миграция существующих
   заказов, `create_order()` v5, `draft_admin_bundle()` v2 (блок promos),
   `draft_clients_bundle()`, функции-ключи `draft_phone_key`/`draft_email_key`.
   Скрипт идемпотентен: повторный запуск пропускает уже связанные заказы
   и уже заполненные скидки.
   Самопроверка в конце: `orders_linked = orders_total`, `discounts_missing = 0`,
   `client_policies = 4`, `clients_total = clients_in_bundle` (> 0, если заказы были).
2. Push в `main` → Pages за 1–2 минуты → **Ctrl + F5**.
3. Чек-лист приёмки:
   - **«Статистика»:** четыре подвкладки. «Заказы» — всё прежнее содержимое
     без изменений (KPI, дни, воронка, топ товаров, доставка/оплата, CSV).
     «Акции» — период по умолчанию «Всё время»; KPI (заказы с кодом, доля,
     сумма скидок, средняя скидка, средний чек с кодом); график «Использование
     кодов по дням» (заказы + скидки ₽); «Статистика по кодам» с переключателем
     «Диаграмма / Таблица» (в таблице: скидка, заказы и скидки за период,
     использовано всего, пилюля статуса кода); «Сводка по кодам»; блок
     «С кодом и без кода»; «Выгрузить CSV» отдаёт три раздела
     (KPI, по дням, по кодам), файл открывается в Excel.
     «Администраторы» и «Клиенты» — аккуратные заглушки со списками планируемого
     функционала и объяснением, почему пока заглушки.
     Прямые ссылки: `admin.html#stats` (заказы), `admin.html#stats-promos` (акции).
   - **Промокоды:** у «Магазина» подвкладки «Категории / Бренды / Товары /
     Комплекты» (без промокодов), вкладка топбара «Магазин» ведёт на категории;
     у «Управления» подвкладки «Оплата и доставка / Промокоды / Сайт /
     Карта сайта / Брендбук»; на странице промокодов активна вкладка
     «Управление»; на карте сайта узел «Промокоды» — в группе «Управление»,
     в группе «Магазин» появились «Комплекты», в «Управлении» — «Брендбук».
   - **Брендбук → админка:** «Управление → Брендбук» → изменить акцентный цвет
     → «Сохранить цвета» → открыть ЛЮБУЮ страницу админки с Ctrl + F5 —
     палитра применена и там (топбар, плашки, кнопки), без «моргания»;
     переключатель темы в админке перечитывает токены (цвета не «залипают»
     от прошлой темы); витрина работает как прежде.
   - **Клиенты:** «Пользователи → Клиенты» — реальные строки из базы: ваши
     тестовые заказы собраны в клиентов (один телефон = один клиент, даже если
     заказов несколько); контакты маскированы, «показать/скрыть» работает;
     сортировка кликом по ФИО/датам/сумме/количеству; пагинация при > 30;
     клик по ФИО — карточка с агрегатами, правка ФИО/телефона/e-mail/
     комментария сохраняется в базу (повторное открытие — данные на месте);
     телефон чужого существующего клиента — понятная ошибка, не «поломка»;
     «Выгрузить CSV» — файл с BOM и «;», колонка «Оплачено, ₽»;
     новый тестовый заказ на витрине (тот же телефон) — клиент не дублируется,
     у него +1 заказ и обновлённая сумма.

## 4. Финальная проверка

Локально перед коммитом: `python3 tests/check-repo.py` (выход 0).
Зеркало просмотра: `cd /home/user && cp sisku-draft/*.html sisku-draft/README.md sisku-draft/LICENSE.md sisku-draft/SECURITY.md sisku-pages/`.
Актуальный архив: `sisku-draft.zip`.

## Откат

Revert коммита. База: скрипт 15 безопасен — колонки `client_id`,
`promo_discount`, `look_discount` и таблица `clients` могут остаться
(старый код их просто не читает); `create_order()` v5 обратно заменяется
повторным выполнением скрипта 14 (v4).
