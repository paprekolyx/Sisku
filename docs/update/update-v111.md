# Инструкция по обновлению черновика до v0.11.1-draft

**Куда смотреть:** этот файл — порядок применения обновления v0.11.0 → v0.11.1
(patch-волна: SQL-регламент и переписанные самопроверки скриптов).

## 1. Файлы для загрузки (по папкам, откуда брать)

- **Корень репозитория:** `README.md`, `SECURITY.md`, `LICENSE.md`
- **supabase/:** `11_product_management.sql`, `12_manage_policies.sql`, `13_reserve_and_looks.sql`, `14_brandbook.sql`, `README.md`
- **docs/:** `update-v111.md`
- **tests/:** `check-repo.py`

## 2. Версия

В `assets/js/config.js` поменять только строку
`const SITE_VERSION = '0.11.0-draft';` → `'0.11.1-draft';`. Ключи базы не трогать.

## 3. База, публикация и проверка

1. Если скрипты 11–14 уже выполнялись с ручной правкой `policyname` — повторно
   выполнять их **не нужно**: правка волной затронула только строки самопроверок.
   Если выполнялись не до конца или с ошибкой 42703 — выполнить исправленные
   версии целиком (все идемпотентны).
2. Push в `main` → Pages → **Ctrl + F5** (визуальных изменений нет).
3. Чек-лист: `python3 tests/check-repo.py` проходит; в Supabase повторный запуск
   любого из скриптов 11–14 завершается без ошибки 42703 и выводит самопроверку.

## 4. Финальная проверка

Локально: `python3 tests/check-repo.py` (выход 0). Зеркало:
из рабочего каталога аналитика `cp sisku-draft/*.html sisku-draft/README.md sisku-draft/LICENSE.md sisku-draft/SECURITY.md sisku-pages/`.
Архив: `sisku-draft.zip`.

## Что зафиксировано регламентом (supabase/README.md, правила 4–6)

- колонка системного каталога политик — **`pg_policies.policyname`**, писать
  `policy_name` запрещено (автотест падает);
- доллар-квоты только парные `$$ … $$` (автотест падает на одиночном `$`);
- скрипты, которые могут уехать не в тот проект Supabase, начинаются
  с префлайта `to_regclass(...)`.
