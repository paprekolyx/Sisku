«Матрица доступа.docx», переданный ведущим аналитиком; содержание таблицы
воспроизведено дословно, служебные блоки помечены явно.
**Ведёт:** аналитик проекта · Albert23NO@ya.ru
**Назначение:** единый источник правды по правам ролей админ-панели боевой

## 1. Список ролей

- **Администратор (admin)** — 2 чел.
- **Менеджер (manager)** — 3 чел.
- **Сборщик (assembler)** — 2 чел.
- **Бизнес-партнер (partner)** — 2 чел.

**Комментарий (дословно из источника):** в скобках указано название на
английском языке — используется в коде. Через тире указано приблизительное
количество сотрудников на первом этапе (возможно расширение в дальнейшем).
**Владелец проекта и ведущий аналитик имеют роль Администратор (admin) — их
доступы к функционалу не могут быть ограничены.**

## 2. Матрица доступа

Легенда: **«+»** — полный доступ; **«±»** — ограниченный (условие в скобках);
**«−»** — нет доступа; **read-only** — только просмотр.
Пометка **«ПЛАН»** — функционал ещё не реализован (план развития:
`docs/feature-proposals.md`, волны `docs/plan/migration-plan.md`); права
строки применяются одновременно с реализацией функционала.

### Заказы

| Функционал | admin | manager | assembler | partner |
|---|---|---|---|---|
| Заказы: просмотр всех | + | + | + | + |

## 3. Служебные отметки аналитика (не изменяют содержание матрицы)

1. **Ролевая модель (матрица) — read-only для всех ролей, включая admin:**
   изменение матрицы — только решением владельца с обновлением этого документа;
   в админке (М2+) матрица отображается без возможности правки.
2. **Связь с ответом 3.6 опросника:** промокоды создаёт только владелец —
   в матрице это право admin (владелец входит в роль admin); manager/partner —
   создание/отключение без удаления в рамках своих строк.
3. **Отличия от черновика (Приложение А `docs/priemka/priemka-v014.md`):**
   роль **partner** существенно расширена (заказы с ПДн, статусы, оплата,
   клиенты, каталог ±, выгрузки CSV); **assembler** видит все заказы и
   переводит «Сборка → Отправлен» (в черновике — «Сборка → Собран», только
   очередь сборки); добавлены строки: просмотр ПДн, статистика администраторов,
   бейджи, закупки/инвентаризация, оплата и доставка, шаблоны уведомлений,
   акции, история заказов и имён, журнал действий. Черновик рекомендовал для
   partner «финансовую сводку без ПДн» (152-ФЗ: минимум необходимого) —
   согласованная редакция расширяет доступ partner к ПДн; это **осознанное
   решение владельца** (05.10.2026), учитывается при реализации M2 и в
   юридическом контуре M4 (роли и объём доступа фиксируются в политике ПДн).
4. **Персональный состав** (ФИО, почта, мессенджер по каждой роли) и создание
   актуальных аккаунтов — ответственность владельца (ответ 3.7; срок — до M2).
   Состав на первом этапе: admin 2 (владелец + аналитик), manager 3,
   assembler 2, partner 2.
5. **«ПЛАН»-строки** привязаны к волнам: возвраты — M4 (предложение №3),
   статистика клиентов/администраторов — M3 (записки 23/26, №10), бейджи —
   M5/v1.x (№16), закупки/инвентаризация — №9, шаблоны уведомлений — M1/M4
   (`notification_templates`), акции — v1.x (№17), история заказов и имён —
   v1.x (№1, П8а), ролевая модель и журнал действий — M2 (записки 31/38).
