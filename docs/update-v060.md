# Инструкция по обновлению черновика до v0.6.0-draft

**Куда смотреть:** этот файл — порядок применения обновления v0.5.0 → v0.6.0.
Пути — от корня репозитория `Sisku`.

---

## Шаг 1. База данных (Supabase → SQL Editor)

Выполнить одним запросом **`supabase/10_promo_and_tracking.sql`** (идемпотентен):
таблица `promo_codes`, колонка `orders.promo_code_id`, функции `check_promo`,
`create_order` v2 (промокод пересчитывается на сервере), `track_order`
(отслеживание покупателем: номер + 4 цифры телефона или 4 символа почты до @).

**Проверка:** финальный select вернёт `promo_rows = 0`, `promo_column_ok = promo_code_id`.

## Шаг 4. Публикация и проверка

1. Push → Pages → **Ctrl + F5**.
2. Чек-лист:
   - статистика: график по дням идёт слева направо от старых дат к новым; по умолчанию открыта «Таблица» в блоке «Доставка и оплата», переключение не дёргает верстку; столбцы диаграмм тонкие;
   - кнопка «Выгрузить CSV» в статистике отдаёт файл со всеми разделами (KPI, дни, воронка, топ, доставка, оплата, время статусов);
   - карточка заказа: пилюля статуса крупная и яркая;
   - «Сборка»: наведение подсвечивает весь заказ целиком (все строки группы);
   - «Магазин»: создайте промокод (например, SISKU10, 10%, без лимита) → в форме заказа на витрине введите код и «Применить» → скидка видна в сводке и пересчитывается на сервере при отправке (проверьте: сумма заказа в админке уже со скидкой, `used_count` увеличился);
   - отслеживание: в контактах и на экране успеха откройте модалку, введите номер тестового заказа и 4 последние цифры телефона из заказа → история статусов с датами, без упоминания ролей; неверный код → «Заказ не найден…»;
   - «Условия заказа»: под тремя плашками — таблица размеров XS–XL с обхватами.
3. Локально: `python3 tests/check-repo.py`.

## Откат

Revert коммита; функции из скрипта 10 можно удалить (`drop function track_order(integer, text);`
и вернуть `create_order` из редакции 0.4.0 при необходимости), таблицу `promo_codes`
оставить пустой или удалить после очистки `orders.promo_code_id`.
