## 4. Осознанно отложено до боевой версии (не чиним в черновике)

| Замечание | Почему отложено | Куда денется |
|---|---|---|
| Supabase-клиент и anon-ключ во фронте | черновик живёт на Supabase по дизайну | миграция M1: свой API, ключей в браузере не будет |
| Агрегаты статистики считаются на клиенте по полной выборке заказов | на объёмах черновика (<100 заказов) это мгновенно и просто | M3: серверные агрегаты |
| Мок-авторизация (пароль в коде страницы), SHA-256 без соли в `admin_users`, anon-запись в `admin_users` | демонстрационные допущения, задокументированы в SECURITY | M2: bcrypt/argon2id, сессии, роли, ACL |
| Вес изображений (hero ~5 МБ, товары по 4–6 МБ) | для демонстрации на Pages терпимо; сжимать сейчас — терять качество превью для владельца | M5: WebP 1600/600px, бюджет страницы |
| По document-listener'у на каждый кастомный селект в `ui.js` | на ~10 селектах незаметно; усложнение кода не окупается | при переносе в боевой фронт — делегирование |
| Автотесты бизнес-логики (SQL-тесты цен/переходов, jsdom-тесты форм) | в черновике логика ещё будет переписываться на PHP | M1–M2: перенос тестов из учебного проекта |
| Линтеры/форматтеры (eslint, stylelint) | черновик читается руками, стиль единообразен | по желанию на боевом фронте |

## 5. Тестирование: что есть и как пользоваться

1. **Авто:** `python3 tests/check-repo.py` — целостность файлов, ссылок, id, CSV,
   версий, синтаксиса SQL и HTML. Запускать перед каждым коммитом.
2. **Ручной чек-лист приёмки** — в `docs/update-v040.md`, шаг 4 (вход, сортировки,
   блокировки, валидации, брендбук, статистика, новые страницы).
3. **Ручные смоук-сценарии** (пройдены при ревью): заказ витрина→БД→админка→статусы→
   «Сборка»→статистика; создание и редактирование пользователя; вход/выход; сортировки;
   обе темы на витрине и в админке; мобильная раскладка админки.
4. **Регрессия после правок:** сначала check-repo, затем чек-лист волны.
