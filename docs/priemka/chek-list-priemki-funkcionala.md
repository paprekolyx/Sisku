# SISKU · Чек-лист приёмки функционала с владельцем

**Статус:** универсальный рабочий документ — не привязан к одной версии сайта.
**Первая редакция составлена:** 07.10.2026 по состоянию сайта **0.17.0-draft**
(актуальная версия всегда видна в подвале витрины и в топбаре админки).
**Правило обновления:** только по запросу аналитика. В следующих волнах чек-лист
самостоятельно не обновляется: новый функционал волны сначала принимается по
чек-листу её инструкции (`docs/update/update-v0XXN.md` §4), после чего по
отдельному запросу вносится сюда.

## Как работать с чек-листом

- Проверяйте пункты вживую: витрина — `https://paprekolyx.github.io/Sisku/`,
  админ-панель — `…/admin.html` (пароль входа указан на странице входа).
  Админку стоит смотреть и с компьютера, и с телефона.
- Подтверждённый пункт отмечайте `[x]`. Замечания, расхождения и пожелания
  пишите строкой ниже пункта с пометкой «Замечание:» — либо отдельным списком,
  как удобнее.
- Версия в скобках в конце пункта — справочная отметка о том, в какой версии
  сайта функционал был реализован. Проверять её не нужно.
- Блоки «Не реализовано — планируется» — справка: такие пункты принять сейчас
  нельзя, указана версия волны, в которой функционал планируется.
- Блоки «Вопросы владельцу» — что полезно уточнить при приёмке или до старта
  следующих волн. Ответы фиксирует аналитик (вне этого чек-листа).
- Перед проверкой обновляйте страницу с **Ctrl + F5** (тексты и цвета из админки
  подхватываются после полной перезагрузки).

## Корзина / заказ

### Корзина (выдвижная панель)

- [ ] Открывается кнопкой в шапке; при открытой корзине фоновая страница не прокручивается (v0.16.0).
- [ ] Позиция корзины: фото, название, бренд и вариант, степпер количества «− / +», сумма строки, кнопка «убрать» (v0.7.0).
- [ ] Добавить больше, чем есть на складе, нельзя — понятное сообщение об остатке (v0.9.1).
- [ ] Повторное добавление того же товара и варианта увеличивает количество (дубли не плодятся).
- [ ] «Очистить» — полная очистка корзины, тост «Корзина очищена» (v0.2.0).
- [ ] «Итого» — сумма позиций; кнопка «Оформить заказ» (неактивна при пустой корзине); пустая корзина — «Корзина пуста».
- [ ] Корзина хранится в браузере (localStorage): переживает перезагрузку страницы; на другом устройстве/браузере — своя (синхронизация появится с кабинетами покупателя в боевой версии).
- [ ] После удаления товара комплекта скидка комплекта пересчитывается (см. «Комплекты»).

### Форма заказа (модальное окно)

- [ ] Сводка: товары, скидка промокода, скидка комплектов, доставка («от N ₽» или «бесплатно»), «Итого».
- [ ] Поля: Имя*, Телефон*, E-mail (необязательное), «Город и адрес / пункт выдачи», Оплата (селект активных способов), Доставка (селект активных способов с ценой), Промокод, Комментарий, чекбокс согласия.
- [ ] Подсказки под полями (а не внутри полей) — тексты из админки (v0.15.0); на мобильных селекты и суммы адаптированы (v0.16.0).
- [ ] Валидация: имя обязательно; телефон — российский формат (+7 (999) 123-45-67 или 8 999 123-45-67); e-mail — формат; ошибки подсвечиваются под полями (v0.4.0).
- [ ] Промокод: «Применить» — проверка на сервере (сроки, минимальная сумма, лимит использований); сообщение об успехе (с суммой скидки) или о причине отказа; коды с витрины не читаются.
- [ ] При любом изменении корзины промокод перевалидируется: если условия перестали выполняться — скидка снимается с понятным тостом (v0.14.1).
- [ ] Чекбокс согласия с политикой ПДн и офертой — без отметки заказ не отправляется; ссылки открывают юрстраницы (v0.15.0).
- [ ] Скрытое антиспам-поле (honeypot) — боты заполняют, люди не видят.
- [ ] «Отправить заказ» — кнопка блокируется на время отправки (двойной клик не создаёт второй заказ).

### Создание заказа (серверные гарантии — проверить контрольным заказом)

- [ ] Цены, остатки и скидки сервер берёт из базы: подделать сумму из браузера невозможно; заказ создаётся одной транзакцией (v0.1.0).
- [ ] Ограничения: 1–99 шт на позицию, не более 50 позиций, текстовые поля не длиннее 1000 символов — с читаемыми ошибками (v0.17.0).
- [ ] Анти-спам: не более 3 заказов за 10 минут на один телефон/e-mail.
- [ ] Остатки списываются сразу (резервирование, v0.10.0): два покупателя не купят последнюю единицу одновременно.
- [ ] В позициях заказа сохраняются снапшоты цены/названия/варианта — последующие правки каталога не меняют историю.
- [ ] Клиент автоматически создаётся (или обновляется) в базе «Пользователи → Клиенты» (v0.13.0).

### Экран подтверждения

- [ ] Нейтральный текст подтверждения — без обещаний «мы свяжемся» (формулировка из админки) (v0.15.0).
- [ ] Показаны номер заказа и код подтверждения (4 цифры телефона или 4 символа e-mail) — они нужны для отслеживания.
- [ ] Кнопка «Отследить заказ» — открывает окно отслеживания с подставленным номером.
- [ ] После закрытия окна корзина пуста.

### Корзина / заказ — не реализовано, планируется

- Онлайн-оплата — боевая версия (в черновике оплата происходит вне сайта: перевод/СБП/наличные, отметку «оплачен» ставит менеджер).
- Уведомления владельцу о новом заказе и покупателю о статусах — шаблоны и правила **v0.23.0**, реальная отправка — боевая версия.
- Запись факта согласия ПДн/оферты в базу — боевая версия (сейчас чекбокс — на уровне макета).
- Кабинеты покупателя, кросс-устройственная корзина — боевая версия.

### Вопросы владельцу (корзина / заказ)

1. Способы оплаты: текущий состав (СБП, перевод на карту, наличные при самовывозе) — окончательный? Какой регламент подтверждения оплаты на старте?
2. Доставка: состав и цены (самовывоз 0 ₽, курьер Москва 600 ₽, СДЭК 300–900 ₽, Почта России 300–800 ₽) — верны? Как покупатель узнает точную цену внутри вилки?
3. Форма заказа: e-mail оставить необязательным? Нужны ли индекс/регион отдельными полями?
4. Ограничения (1–99 шт, ≤50 позиций, анти-спам 3/10 мин) — не помешают ли реальным покупателям и крупным заказам?
5. Промокоды: хватает ли механик (процент/сумма, минимальная сумма, сроки, лимит использований)?
6. Текст подтверждения заказа: что обещать покупателю (кто и когда свяжется)?
7. Формулировка чекбокса согласия — устраивает ли до финальной юридической проверки?

## Отслеживание / возврат

### Отслеживание заказа (модальное окно)

- [ ] Открывается кнопкой «Статус заказа по номеру» в разделе «Контакты» (v0.6.0); тексты окна — из админки (v0.15.0).
- [ ] Ввод: номер заказа + код подтверждения (4 цифры телефона или 4 символа e-mail).

- [ ] Неверный номер или код — понятная ошибка без раскрытия данных.

### Заявка на возврат (из окна отслеживания) (v0.16.0)

- [ ] Кнопка «Оформить возврат» появляется только у заказов в статусах «Отправлен» или «Доставлен».

- [ ] Текст-подсказка про срок возврата (7 дней) — нейтральная формулировка, редактируется из админки.
