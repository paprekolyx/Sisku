## 1. Крупные пункты — записаны в план разработки

### З1 (плановая часть). Товар без вариантов — авто-вариант «One Size» (L · v1.0, волна M1 → FP №23)
**Проблема:** владелец создал «Тестовый товар» (арт. 00001) без вариантов —
карточка отображается некрасиво: размер — «варианты не заданы», кнопка
«В корзину» активна, при нажатии — ошибка «Выберите размер», хотя реальная
причина — товара нет в наличии. Тот же эффект в комплекте с таким товаром
(«Тестовый комплект»). Это живой пример записки 30 приёмки v0.14.x: в бою
нужна возможность создать товар без вариантов / с универсальным вариантом
под капотом.
**Состояние кода:** `assets/js/site.js:482` («варианты не заданы»),
`site.js:368` (пустой option «Выберите размер…»), `site.js:406` (тост
«Выберите размер для всех товаров комплекта»); наличие считается по сумме
вариантов — без вариантов всегда 0.
**Решение:** баг-часть (карточка товара без вариантов должна показывать
«нет в наличии» и не предлагать «В корзину» с вводящей в заблуждение
ошибкой) — в волну v0.16.0 (§2.1); плановая часть — авто-создание скрытого
варианта «One Size» при сохранении товара без вариантов — **FP №23**
(v1.0, волна M1, `migration-plan` §4.8 записка 30 — уже зафиксирована).
**Категория/объём:** Б + ПЛАН; S (баг) + L (M1).

### З4. Воронка статусов: настраиваемая пара + время перехода (M · бой M3 → FP №10)
**Проблема:** в «Статистика → Заказы» нужна возможность настроить два

### 2.1. З1-баг. Карточка товара без вариантов (S · site.js)
Товар без вариантов (или с нулём наличия по всем вариантам): в карточке —
состояние «нет в наличии» (`site.js:329` — плашка есть, продублировать в
модалку), кнопка «В корзину» — неактивна/скрыта с причиной «товара нет в
наличии»; тост «Выберите размер» (`site.js:406`) — только когда вариант
реально есть, но не выбран. Комплект с товаром без вариантов — та же
логика в модалке комплекта (`site.js:419-422` — текст «нет варианта»
заменить на «нет в наличии», если вариантов нет вовсе).

### 2.2. З2. Комплекты: единственный вариант — выбран по умолчанию (S · site.js)
В модалке комплекта («Подарок из Франции»): если у товара ровно один
вариант — он выбирается по умолчанию (без «Выберите размер…»); проверка
`site.js:406` при этом не срабатывает ложно.

### 2.3. З6. Статистика → Акции: по умолчанию таблица (S · admin.js:16)
`promoMode: 'chart'` → `'table'` (аналогично `funnelMode` — правка 2.12
волны v0.15.0); переключатель «диаграмма/таблица» сохраняется.

### 2.4. З7. Брендбук: hex-поля в тёмной теме (S · admin.css + brandbook.js:111-112)
В тёмной теме админки поля ввода hex (`.bbe-hex`) и сопутствующие —
тёмный фон/светлый текст (переменные темы); светлая тема витрины остаётся
яркой — это ожидаемое поведение, инвертируются только элементы управления
редактора. (Смена шрифта страницы брендбука — отдельная отложенная задача
АН-10, в волну не входит.)

### 2.5. З8. Битые mailto-ссылки админов (S · users.js ~80)
Ссылка `mailto:` генерируется только для валидного e-mail
(`SiskuUtil.emailOk`); для старых данных («-» и прочий мусор) — обычный
текст без ссылки. `tel:`-ссылка уже санируется (`users.js:82`) — привести
e-mail к тому же паттерну. Новые записи с «-» не создаются (валидация
формы есть) — правка только на отображение старых данных; чистка данных —
за владельцем (не блокирует).

### 2.6. М1. Отступы hero на мобильных (S · styles.css:157)
`.hero-in { padding: 96px 0 }` — добавить горизонтальные отступы на узких
экранах (медиа-запросы ≤720/≤560), тексты hero не должны касаться рамки
экрана; проверить и другие полноширинные секции витрины.

### 2.7. М2. «Быстрый просмотр» на тач-устройствах (S · styles.css:211-219, site.js:324)
Кнопка «Быстрый просмотр» — только для устройств с наведением:
`@media (hover: none) { .card-media .quick { display: none } }` (или
аналог) — на мобильных она мелькает при тапе и не нужна.

### 2.8. М3. Скролл сайта при открытой корзине (S · site.js:596-598)
Drawer корзины открывается без блокировки фонового скролла — добавить
`document.body.style.overflow = 'hidden'` при открытии и восстановление при
закрытии (паттерн модалок уже есть: `site.js:582-583`). Повтор бага
учебного проекта PaprekolyX — учтено в проверке волны.

### 2.9. М4. Форма заказа на мобильных (M · index.html, styles.css)
Выпадающие списки оплаты/доставки (`index.html:261` и соседние поля) уходят
вправо — проверить отступы/ширину в медиа-запросах (слева отступ
нормальный, справа — нет); крупные рублёвые суммы (скидка по промокоду)
переносятся на две строки со «съехавшим» знаком ₽ — `white-space: nowrap`
/компактный размер; hint промокода (`styles.css:517`) не помещается —
формулировку сократить нельзя (смысл), адаптировать раскладку (переносы,
кегль, ширина).
