# Инструкция 2. Вторая база Supabase и подключение ключей

## Можно ли две независимые базы из одного аккаунта?

**Да.** В Supabase «база» = «проект». В одном аккаунте (и в одной организации)
можно создать несколько проектов, и каждый — это полностью независимый
PostgreSQL со своими таблицами, ключами и RLS: учебный `PaprekolyX` и новый
`Sisku` не пересекутся никак.

Ограничение бесплатного тарифа: **2 активных проекта** на организацию.
У тебя как раз будет два: учебный + черновик Sisku. Если захочется третий —
придётся удалить (pause) один из старых или перейти на платный тариф.
Данные проектов изолированы: ключи от одного проекта не дают доступа к другому.

## Шаг 1. Создать проект

1. Зайти в свой аккаунт https://supabase.com/dashboard.
2. Организацию выбрать **ту же**, где учебный проект (переключатель в шапке).
3. **New project**:
   - Name: `sisku-draft`;
   - Database Password: придумать и **сохранить** (в браузере/менеджере паролей) —
     он нужен только для прямого доступа к БД, сайт работает без него;
   - Region: для черновика любой (например, Frankfurt — ближе к России из
     бесплатных регионов). *Для боевой версии выберем российское решение,
     см. отчёт по проекту, раздел 2.*
4. Дождаться создания (~1–2 минуты).

## Шаг 2. Применить SQL-скрипты

В проекте `sisku-draft`: **SQL Editor → New query**. Выполнять **по порядку**,
каждый файл отдельным запросом (Run):

| Порядок | Файл из папки `supabase/` | Что делает |
|---|---|---|
| 1 | `01_schema.sql` | таблицы каталога, заказов, справочников + RLS |
| 2 | `02_rls_and_access.sql` | политики чтения (каталог публичен; заказы читаются — черновик без пароля) |
| 3 | `03_functions.sql` | `create_order()`, `admin_set_status()`, `admin_set_paid()` |
| 4 | `04_seed_references_and_content.sql` | статусы, модель переходов, оплата/доставка, тексты Sisku |

Все скрипты идемпотентны: повторный запуск ничего не ломает.

## Шаг 3. Загрузить товары из CSV

**Table Editor** → выбрать таблицу → ⋯ → **Import data from CSV** (или кнопка
Import). Порядок важен из-за внешних ключей:

1. `data/brands.csv` → таблица `brands`
2. `data/categories.csv` → таблица `categories`
3. `data/products.csv` → таблица `products`
4. `data/variants.csv` → таблица `product_variants`

Перед импортом галочки «первая строка — заголовки» включены по умолчанию.
После импорта в Table Editor должно быть: 6 брендов, 6 категорий, 8 товаров,
20 вариантов.

## Шаг 4. Взять ключи и вставить их в HTML

1. В проекте `sisku-draft`: **Settings → API** (в новом интерфейсе —
   кнопка **Connect** слева → вкладка **API keys**).
2. Скопировать два значения:
   - **Project URL** — вида `https://xyzabcsupabase.co`;
   - **anon public** key — длинная строка, начинается с `eyJ…`.
     Это ПУБЛИЧНЫЙ ключ, его место в коде сайта. Секретный ключ
     (`service_role` / `sb_secret_…`) не копируем никуда: он обходит RLS.
3. Открыть файл **`assets/js/config.js`** (это единственное место, куда
   вставляются ключи) и заменить две строки-заглушки:

```js
const SUPABASE_URL = 'https://ВСТАВЬТЕ-PROJECT-URL.supabase.co';   // ← сюда Project URL
const SUPABASE_ANON_KEY = 'ВСТАВЬТЕ-anon-public-KEY';               // ← сюда anon public
```

4. Сохранить, закоммитить (git push или правка через веб GitHub).
5. Обновить сайт с **Ctrl + F5**: каталог загрузится из базы, тексты
   подставятся из `site_content`.

## Проверка

- Витрина: 8 товаров, фильтры по 6 категориям и 6 брендам, тексты Sisku.
- Оформление тестового заказа → на экране номер заказа; в Table Editor →
  `orders` появилась строка, `product_variants.stock` уменьшился.
- `admin.html`: заказ в списке, смена статуса по модели переходов
  (new → confirmed → paid → …), отметка оплаты, вкладка «Статистика» с графиками.

## Важные ограничения черновика

- База Supabase находится **вне России**: реальные персональные данные
  покупателей сюда вводить нельзя (152-ФЗ). Только тестовые заказы
  («Тест Тестович», +7 000…). Для боевой версии — российское решение
  из отчёта, раздел 2.
- Админ-панель без пароля: ссылку на `admin.html` не публикуем,
  в индексы поисковиков страница не попадёт (тег noindex), но знай:
  любой, у кого есть ссылка, увидит список заказов. Это осознанное
  упрощение макета.
